## 重要

今回実装したBilinear方式は、配線確認とテスト専用です。完成品の最高画質処理には使用しません。

現行の品質経路は`mobileStackAdaptive`という独自方式だけを本番候補として扱い、AMaZEのenumとプレースホルダーも削除しました。RawTherapeeやdarktableなどGPL系実装のコードは使用しません。Dart、Node、Native C11には、4つの片側ラプラシアン補正候補と4つの象限候補を独立に作り、グリーン輝度プロキシの3×3構造テンソルで平坦部・滑らかな勾配・単一エッジ・周期テクスチャ・点状構造を分類して保守的な水平／垂直推定と融合する独立実装があります。R-GとB-Gも、グリーン差だけでなく局所方向エネルギー、コヒーレンス、テクスチャ信頼度で重みを適応させ、最後に星コア保護付き3×3中央値で孤立色差を抑えます。Work33固定版との64×56合成比較では、斜め無彩色エッジMSEを約26%、斜め色エッジMSEを約13%低減し、滑らかな斜め勾配と周期テクスチャは実質同等でした。Gaussian星像MSEは約0.25%増のため今後の実コーパス調整対象ですが、孤立した星中心の保持契約は通過しています。全計算は非再帰で、読み取り半径4をDartとNativeの公開定数として維持し、不足する内部タイル入力は処理前に拒否します。Native Cは呼び出し側所有バッファだけを使用するタイルAPIとしてAndroid/iOSビルドへ追加しましたが、この環境ではコンパイルできず、Dart FFI接続と実カメラ品質評価もまだ未完了です。そのため本番品質フラグはfalseのままとし、診断方式へ降格せず明示的に停止します。

Native RAW ABI v1は構造と8つの公開シンボルを変更せず、タイル分割JPEG Lossless（SOF3）とSony ARW2圧縮32767の能力ビットを公開します。C側は2×2 Bayer RGGB CFAをフルセンサーFP32モザイクへ展開します。ARW2は16画素単位の適応残差を検証し、格納11bit値をカメラの14bitセンサー尺度へ展開します。その他のARW圧縮方式と、ARW以外のフル画素デコーダーはまだ含まれません。Sony `WB_RGGBLevels`タグがある場合は、2つの緑の平均を1.0とする4成分カメラWBを返します。ガンマ、オートブライト、ホワイトバランス、ブラックレベル補正、デモザイク、縮小はネイティブ読込時に適用しません。

Android/iOSの画素デコード経路は、特別なテストURIの2×2適合モザイクに加え、上記契約へ一致する実ARWパスをデコードします。可逆JPEG ARWはワーカーIsolateでFP32 CFAへ展開され、検証後に品質パイプラインの一時`PipelineContext`へ渡されます。そこでActiveArea左上を原点とする2×2ブラックレベルを減算し、DNG処理モデルと同じく`WhiteLevel - max(BlackLevel)`で線形正規化した後、任意の4成分カメラWBを画像CFA位置ごとに乗算します。補正は同じFP32バッファ上でチャンク実行し、追加のフルフレームコピーを作りません。初期ノイズ処理とHDRヘッドルームのため負値と1.0超はこの段階ではクリップしません。

既定の画素上限は64MPで、フルフレームRAWジョブは全工程を単一レーンで実行します。これにより前のジョブがFP32 CFAを保持中に次のデコードを重ねません。一致しないARW、未対応圧縮、登録済みフル画素デコーダーがない他形式の通常パスは未対応エラーとなり、実RAWを誤って処理済みとして扱いません。

不良画素補正は、カメラまたは信頼済みRAWメタデータが画像座標を明示した点だけを対象にします。単一フレームの輝度だけでホットピクセルを自動判定しないため、星や合法な点光源を黙って除去しません。補間は同じCFA位相にある水平・垂直・対角の対向近傍を比較し、差が最小の方向を平均します。画像端では利用可能な同一位相近傍の中央値を使い、リスト中の全欠陥は補間元から除外します。欠陥マップが未接続の現在のARW経路は明示的にスキップし、画素を変更しません。

デモザイク段は`DemosaicRegistry.requireProduction(mobileStackAdaptive)`を通過したエンジンだけを実行します。CFA入力は24画素の重なりを持つタイルとして要求し、エンジンは中央の非重複領域だけをFP32 RGBで返します。タイルの絶対座標、寸法、サンプル数、全有限値を検証し、計画順にOS一時領域の専用ファイルへ直接書きます。全タイルが成功した場合だけ保存先をコミットしてCFA所有を解放し、失敗・不一致・非有限値・キャンセルでは部分ファイルと専用ディレクトリを削除して補正済みCFAを保持します。

RGBの永続一時容量は1画素12バイトなので64MPで768,000,000バイト必要ですが、RAM上のRGBは既定1024×1024タイル1枚の12,582,912バイトを基本上限にできます。CFA本体は引き続き1画素4バイトで保持します。後続の位置合わせ、スタック、Drizzleも`readRegion`で必要領域だけを読み、フル画面RGBへ戻さない方針です。一時保存先の空き容量検査と予約は後続実装で追加します。

位置合わせ済みRGBの生成は`AffineSamplingTransform`で出力座標から入力座標への逆写像を固定し、`TiledAffineRgbResampler`が各出力タイルの四隅から必要入力矩形とバイリニアhaloを求めて`readRegion`を1回だけ呼びます。回転と並進は1回の補間へ融合し、フルフレーム回転バッファやシフトバッファを作りません。入力画像外へ写る画素はゼロ値とcoverage 0を返し、端画素を複製して実観測として混ぜません。coverage 0は後続の棄却スタックとDrizzleで必ず除外します。

棄却合成は`TiledKappaSigmaCombiner`が出力タイルを最大65,536画素の行バンドへ再分割し、各フレームのcovered RGBを逐次再読込してFP64で重み付き平均・分散・候補生存数を計算します。最大3反復の各統計パスと最終平均でI/Oとアフィン補間を繰り返す代わりに、整列済みフレーム列をRAMへ保持しません。coverage 0は全統計から除外し、Kappa閾値適用後に最低生存数を割る場合はその棄却を無効にします。結果にはRGBチャンネルごとの生存観測数を付け、値0の実画素と観測なしを区別します。`TiledRegisteredRgbStacker`がファイルバックストア、逆写像変換、品質重みをこの合成器へ直結します。

全画像処理は`TiledRegisteredRgbStackPipeline`が出力計画順に各合成タイルを生成し、FP32 RGBとRGB別uint16生存観測数を別々のファイルバックストアへ直接書きます。RGB全タイルとcount全タイルが揃って両方のflushが成功した場合だけ結果の所有権を返します。第2ストアの生成、任意タイル処理、書込、commitのいずれかが失敗またはキャンセルされた場合は、先に作成・commitされた側も含めて両方をabortして一時ファイルを削除します。利用側は書出しまたは次段完了後に結果をdisposeします。

独自デモザイクの基準資料には、Bilinearより大きく改善する線形補間を示したMalvar–He–Cutler論文を使います。ただしこの方式だけを最終品質とはせず、方向適応グリーン復元、色差補間、偽色抑制、星像を壊さない局所判定を独自に組み合わせ、公開コーパスで評価してから本番品質フラグを有効にします。資料: https://www.microsoft.com/en-us/research/publication/high-quality-linear-interpolation-for-demosaicing-of-bayer-patterned-color-images/

ABI番号はv1のままです。メタデータ検査は任意シンボルと能力ビットで照会する後方互換拡張で、旧ABI v1ライブラリは従来デコード機能のまま読み込めます。メタデータ結果には画素ポインタを含めず、結果構造とエラーバッファだけを専用release関数で解放します。

DNGメタデータ経路は実ファイルを読み、画像寸法、2×2 Bayer CFA、有効領域、Orientation、黒／白レベル、AsShotNeutral由来のカメラWBを返します。ファイル全体や画素ストリップは読み込みません。Classic TIFFのIFDを最大16個、各IFDを最大512エントリ、SubIFDを最大8個に制限し、すべてのオフセットと要求時のファイル長を検証します。BigTIFF、非Bayer CFA、画素デコードには対応しません。

アプリからの実DNG検査は既定で無効です。検証ビルドだけ`--dart-define=MOBILE_STACK_ENABLE_DNG_METADATA=true`を指定すると、DNGに限ってファイル選択時と品質パイプライン開始時にメタデータ検査を行います。ネイティブ能力ビットがないライブラリは実DNG対応として扱いません。適合テスト用URIは引き続き6000×4000の決定論的な構造情報を返します。

実カメラDNGの検証には`mobile_stack_dng_probe_cli`と`tool/dng_corpus/verify_dng_corpus.mjs`を使用します。事前準備用の`inventory_dng_corpus.mjs`はユーザー所有フォルダーを再帰走査し、symlinkを追跡せず、相対パス・容量・SHA-256・安全なID候補だけを未検証draftへ記録します。`create_manifest_draft.mjs`はインベントリを厳格に再検証し、その生バイトSHA-256を固定して、provenance・reference・expectedを`null`で残す未完成の執筆用下書きを生成します。この下書きは検証マニフェストとは別契約であり、検証器は受理しません。人が全ブロックを確認・記入した後、`finalize_manifest.mjs`が下書きと元インベントリの機械項目・生バイトSHAを照合し、現在の全DNGについてsymlinkを拒否して容量とSHA-256を再検証します。すべて成功した場合だけ正式マニフェストを原子的に作成します。出典・ライセンス・参照ツール・期待値は自動生成せず、入力内容の真実性は人が独立に確認する必要があります。コーパスはファイル長・SHA-256・出典・ライセンス・再配布可否・参照ツールと期待値が揃わなければ受理しません。検証器は最大8並列・各サンプル最大100反復・各プローブ100ミリ秒～5分のタイムアウトに対応し、完了順にかかわらずマニフェスト順の結果を生成します。最初の失敗で新規実行を止め、実行中の並列プローブも中断します。Ctrl+C／SIGTERMはストリームハッシュとNative子プロセスへ伝播し、終了を待ってからレポートを生成せずに停止します。任意の監査JSONはすべての実行が成功した後だけ原子的に作成し、既存ファイルを上書きしません。第三者RAWの無断再配布を避けるため、実画像はこの成果物へ同梱していません。ローカルまたは別管理のコーパスだけを明示的に検証します。

`.github/workflows/native-raw-abi.yml`はFlutter 3.44.7を固定し、UbuntuとmacOSでC ABIテストを実行します。Ubuntuでは別のDebug構成をAddressSanitizer／UndefinedBehaviorSanitizer付きでビルドし、メモリ誤用と未定義動作も検査します。さらにAndroid arm64 APK内の共有ライブラリと、署名なしiOS Debugアプリの実行ファイルから公開シンボルを読み取り、マニフェストとの差分があれば失敗します。

同期FFIは`Isolate.run`内で実行します。ネイティブ所有の結果はワーカー内でDart所有`Float32List`へ1回コピーして解放し、ワーカー終了時に結果のメモリをメインIsolateへ移します。ネイティブポインタをパイプラインへ保持しません。64MP上限では所有権コピー中に2つのFP32バッファが一時的に合計約512MBとなるため、同時RAWジョブ数を1に固定しています。

内部精度はFP32を維持し、FP16、自動縮小、近似演算への自動変更は禁止しています。スタック累積FP64の方針も維持しています。

元RAWは変更せず、プロジェクトファイルは作成しません。一時中間データはセッション終了時に破棄します。

TIFF系RAWではIFD内のJPEGオフセットとサイズ、CR3ではPRVW/THMBボックス、RAFではヘッダー内のプレビュー位置と長さを検証して実プレビューを表示します。プレビューは1枚8MB、選択全体64MBまでに制限します。埋め込みJPEGを取得できないファイルはデザイン上のフォールバック表示を使用します。

提供されたSony ARWを読み取り専用ホストプローブで確認し、37,519,360バイトのLittle-Endian Classic TIFF、5 IFD、3 JPEG候補として解析しました。既存アプリと同じ最大候補選択で、オフセット278,528、1,314,685バイト、7008×4672の埋め込みJPEGを確認しています。

さらにセンサーIFDを解析し、7168×5120、14bit RGGB、512×512タイル140枚、JPEG Lossless SOF3、アクティブ領域7008×4672、Orientation 8、黒レベル512、白レベル16383と確認しました。Sony `WB_RGGBLevels`は2117、1024、1024、2271で、正規化カメラWBは2.0673828125、1、1、2.2177734375です。線形正規化係数は`1 / (16383 - 512) = 0.00006300800201625606`です。全140タイルを参照デコーダーで展開し、補正式を検査点へ適用して有限値を確認しました。row-major uint16 CFAのSHA-256は補正前検証値`5989a02445b8d999760f387818e3c91c1c7cb37a2875ffbbd7b3656a291957d2`から変わっていません。元ARW、埋め込みJPEG、展開CFAは成果物へコピーしていません。実ファイルに対するNative C／Android／iOS実行は、対応コンパイラと実機がある環境でのCI・統合テスト対象です。

CR3の走査は先頭64MBまで、候補は最大32件に制限しています。ボックス境界、画像寸法、JPEG長、JPEGシグネチャがすべて整合する候補だけを読み込みます。

現在ファイル選択画面へ公開する形式は、ヘッダー検査まで接続済みのDNG、CR2、CR3、NEF、NRW、ARW、RAF、ORF、RW2、PEFです。その他のRAW拡張子は将来のデコーダー候補として定義だけを保持しています。

`assets/images/mobile_stack_icon_source.png` は提供されたアイコン原本です。Android/iOSのランチャーアイコンへの変換は、Flutterのプラットフォーム構成を作成した後に行います。
