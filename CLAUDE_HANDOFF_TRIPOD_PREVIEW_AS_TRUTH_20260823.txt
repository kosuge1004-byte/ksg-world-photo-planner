AstroSight Claude引き継ぎ資料
三脚候補点修正：プレビュー側を正（Single Source of Truth）とする
作成日: 2026-08-23

==================================================
0. 最重要
==================================================
このZIPは「修正前の最新基準データ + 修正指示書」です。
三脚候補点の不具合修正そのものは、まだこのZIPには実装していません。
Claudeは、まず実コードを再確認し、下記仕様に従って修正してください。
推測で既存精度・補正・UI仕様を変更しないこと。

ユーザーが実地検証した結果を最優先の正解データとする。
- 実際にその日時・場所に立って確認した三脚位置（スクリーンショットの青線側）で、実景の太陽と被写体の位置関係が一致した。
- 同じ三脚位置をAstroSightのプレビューへ設定したとき、プレビューも実景と一致した。
- しかし自動算出された「太陽 三脚候補」黄色ピンは別地点に出た。
→ よって今回の正は「プレビュー側の正計算」。三脚候補点の逆算側が誤り。
→ プレビューの正計算を変更して候補点に合わせてはならない。

==================================================
1. 修正目的
==================================================
三脚候補点を、プレビューが使う幾何・天体・高さ・補正モデルの逆問題として求める。

必須の成立条件：
「候補点を算出 → その候補点を既存プレビュー計算へそのまま戻す → 天体中心と被写体中心が一致」

この round-trip を満たさない候補点を確定候補として表示してはならない。

==================================================
2. 現コードで確認済みの重要箇所
==================================================
主対象：
- src/cesium/tripodCandidates.ts
- src/App.tsx
- src/cesium/cameraModelFactory.ts
- src/cesium/celestial.ts
- src/height/heightResolver.ts
- src/types/points.ts
- src/cesium/worldTerrain.ts

現行 tripodCandidates.ts には以下がある：
- directSightlineSeedDistanceMeters()（ECEF直線を初期距離推定に利用）
- initialBearing = (point.azimuthDegrees + 180) % 360
- calculateTripodCandidates()

現状の問題：
ECEFの3D直線が最終候補座標の唯一の幾何基準ではなく、天体方位+180°のKarney地表測地線上を探索する経路が残っている。
プレビューの正計算と逆計算が同一モデルではない。

App.tsxには previewViewCorrection が存在し、プレビュー/カメラ投影へ渡されている。
候補計算側では同一条件として扱われていない箇所があるため、意味を確認して整理すること。
ただし重要：UI表示用の手動視線補正を物理的な三脚座標へ無条件に混ぜてはいけない。
「実景に対応する物理カメラモデル」と「表示だけのview correction」を分離し、プレビューで実景一致に使われている最終投影条件をround-trip検証に使うこと。

高さは以下を混同しない：
- ellipsoidalHeightMeters（Cesium/ECEF側）
- orthometricHeightMeters（Astronomy Engine Observer等）
- geoidHeightMeters
候補計算中だけ legacy height を別基準として代用しない。

==================================================
3. 必須修正仕様
==================================================
A. プレビューを正とする
- 既存プレビューの投影結果を変更して黄色候補へ合わせることは禁止。
- 三脚候補計算をプレビューの逆問題として修正する。

B. 天体中心
- 太陽/月は天体円盤の端ではなく中心座標を使用。
- apparent disc radius/diameter は表示専用。三脚候補位置決定に混ぜない。

C. 3D幾何
- 被写体の確定3D座標を基準にする。
- 天体中心の視線方向を、プレビューと同一の座標/補正定義から得る。
- ECEF/WGS84上で「天体中心 → 被写体 → 後方」の3Dレイを構成。
- 三脚候補は、その3Dレイと地形表面の交点として求める。
- initialBearing + Karney測地線探索は、本計算の座標生成器として使わない。
  Karneyは距離/方位検証等に使ってよいが、3Dレイの代替にしない。

D. 地形との複数交点
- レイが地形と複数回交差する場合、全交点を候補として保持。
- 遠い候補を勝手に1点へ絞らない。
- 画角/FOV/焦点距離を理由に候補を削除しない。構図選択はユーザー判断。

E. 高さ基準の統一
- 被写体・候補地点とも HeightResolver / ResolvedGroundPoint の正式情報を使用。
- ECEF/Cesiumにはellipsoidal height。
- Astronomy Engine Observerにはorthometric height。
- geoid heightを明示的に保持。
- 候補算出時と、候補を三脚ピンへ採用した後で高さ基準が変化しないようにする。

F. 最終再計算
各候補交点について正式高さを解決後、候補地点から再計算する：
- 天体中心方位/高度
- 被写体中心方位/仰角
- 必要な大気差/屈折/気象補正
既存の精度補正を省略しない。

G. Round-trip検証（必須）
候補地点を既存プレビューと同じ CameraModel/Projection 経路へ逆投入する。
天体中心と被写体中心のスクリーン座標差を計測する。
- ここで一致しない候補は確定候補にしない。
- ただし画角内/外というユーザー構図条件では除外しない。
- 「同一方向を向いているか」という幾何成立だけを検証する。

H. 旧方式
- 新方式失敗時に旧方式へ自動フォールバックしない。
- 旧方式はハンバーガー「ダブルチェック」ON時のみ独立検算。
- ダブルチェック結果で新方式候補を削除/置換しない。
- 不一致は警告/診断として出す。

==================================================
4. 絶対に維持する精度要素
==================================================
高速化のために以下を落とさない：
- WGS84 / ECEF
- GeographicLib/Karney
- DEMの既存最高精度経路
- ジオイド補正
- 地球曲率
- 大気差/屈折
- 温度・気圧等、現行で有効な気象補正
- Astronomy Engineの現行天体中心計算
- 候補確定時の高精度再収束

DEMサンプル数を単純に減らす、1m相当精密化を粗くする、補正を省く等は禁止。
速度改善はバッチ取得、キャッシュ、重複計算排除、キャンセル等で行う。

==================================================
5. 既存の速度改善を壊さない
==================================================
この基準ZIPには、精度を落とさない性能改善と、交点検出の適応探索/バッチ化が入っている。
それを無条件に巻き戻さない。

特に：
- DEMキャッシュ/IndexedDB接続再利用
- 古いLOS計算のキャンセル
- プレビュー再撮影回数削減
- 複数交点の精密化バッチ取得
- 適応的な交点探索
を維持し、必要なら3Dレイ方式へ適合させる。

==================================================
6. 実証回帰テスト
==================================================
最重要の回帰テストは「今回ユーザーが実地確認したケース」。
スクリーンショットもZIP内 evidence/ に同梱する。

判定：
1) 青線側の実三脚位置を三脚ピンへ設定
2) 同日時・同被写体でプレビュー
3) 実景と同じ太陽/被写体関係になること（現状ここは正）
4) 自動三脚候補計算を実行
5) 自動候補がこの正しい幾何位置へ戻ること
6) 候補を選択してプレビューへ戻しても天体中心/被写体中心関係が変わらないこと

重要：スクリーンショットから座標を推測してテスト値を捏造しない。
正確な緯度経度/日時/被写体座標がコード・保存プロジェクト・ユーザー入力から取れない場合は、テストハーネスを用意し、ユーザーの実データを入力できる形にする。

==================================================
7. 自動テスト追加
==================================================

候補点について、計算後にプレビュー投影へ戻した誤差をログできるようにする。
診断ログ例：
- candidate lat/lon
- ellipsoidal/orthometric/geoid heights
- celestial az/alt
- subject az/elevation
- az error / alt error
- preview screen dx/dy
- terrain source / precision source

8. 完了条件
==================================================
以下すべてを満たすまで「修正完了」としない：
- 実証ケースで自動候補が正しい側へ一致
- 候補→プレビューround-tripが成立
- 高さ基準混在なし
- 太陽/月中心を使用
- 複数交点維持
- 画角による候補自動除外なし
- 旧方式自動fallbackなし
- ダブルチェックは独立検算のみ
- 既存の精度補正を維持
- TypeScriptチェック成功
- build成功（依存取得可能な環境で）
- 既存性能/LOS/メモリ/キャッシュ/三脚候補テストPASS
