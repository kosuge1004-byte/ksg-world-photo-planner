AstroSight 端末間プロジェクト一致修正 V23
作成日: 2026-08-29

症状
- 同じプロジェクトをPCとスマートフォンで読み込んでも、三脚候補点とプレビューが一致しない。
- 両端末とも、保存時に指定した塔頂や確定済み三脚位置と異なる結果になる場合がある。

原因
- 旧共有コードV1は被写体と三脚の緯度・経度だけを保存し、高さと高さ基準を破棄していた。
- 読み込み端末がそれぞれDEM標高を再取得するため、端末・通信・キャッシュ状態によって別の高さになった。
- 3Dで塔頂を選択した被写体も地表高へ戻され、構図計算の入力そのものが変わっていた。
- プレビュー構図補正、屈折補正、精度設定も共有されず、各端末のローカル設定が混入していた。

修正
- 共有コードをV2へ更新し、被写体と三脚の完全なGroundPointを保存する。
  - 緯度、経度、高さ
  - 地表基準高、相対高などの高さ基準情報
- プレビュー構図補正をプロジェクトと共有コードへ保存する。
- 屈折補正、精度、ダブルチェック設定をプロジェクトと共有コードへ保存する。
- V2読み込み時はDEMで高さを取り直さず、保存された同一の確定値をPCとスマートフォンで使用する。
- 旧V1共有コードは互換読み込みを維持する。ただしV1に存在しない高さは復元できないため、読み込み時に旧形式であることを通知する。

旧プロジェクト・旧共有コードについて
- 旧V1に塔頂高などの情報は格納されていないため、自動復元はできない。
- 新版で被写体ピンを正しい塔頂へ置き直し、三脚とプレビューを確認して保存する。
- その後、新しく共有コードまたはQRを作成し、もう一方の端末で読み込む。
- 新版で作成したV2共有コードでは、両端末へ同一の計算入力が転送される。

検証
- TypeScript: npx tsc -b 成功
- 回帰テスト: npm run test:regression 成功（34グループ）
- lint: npm run lint 成功（エラー0、既存警告のみ）
- production build: npm run build 成功
- 新規回帰テストでV2の高さ、高さ基準、構図補正、精度設定が完全一致することを確認
- 新規回帰テストでV1の読み込み互換性を確認

注意
- この修正は端末差と保存時の情報欠落を解消する。
- 旧形式ですでに失われた塔頂高を推測して補うものではない。
- PCとスマートフォンの両方をV23へ更新し、正しいピン位置から新規保存・新規共有すること。
