# R2書き込み予算カウンター(D1)のセットアップ手順

## これは何のための作業か

将来AstroSightの利用者が増えた場合、R2(標高・地形データのキャッシュ保存先)の無料枠(月100万回書き込み)を超えると、支払い方法を登録済みのため自動的に課金される可能性があります。

Cloudflare自体には「無料枠を超えたら事前に完全に止める」機能が存在しないため、AstroSight自身のコードの中で、月間の書き込み総数を数え、無料枠の90%(90万回)に達したら、それ以上はキャッシュへの保存を諦めて直接処理に切り替える(表示は止まらず、速度が落ちるだけ)、という安全装置を追加しました。

この安全装置は、KV(1日1000回書き込みしか使えない)ではなく、**D1というCloudflareのデータベース機能**(1日10万回書き込み、KVの100倍)を使って実現しています。

## 必要な作業(1回だけ)

### 1. Cloudflareダッシュボードで、新しいD1データベースを作成する

1. Cloudflareダッシュボードにログイン
2. 左メニューから **「Storage & Databases」→「D1 SQL Database」** を開く
3. **「Create database」**(データベースを作成)ボタンを押す
4. データベース名に `astrosight-r2-write-budget` と入力して作成
5. 作成が終わると、そのデータベースの詳細画面に**「Database ID」**という、英数字とハイフンで構成された文字列が表示されます。これをコピーしておいてください

### 2. `wrangler.jsonc` の該当箇所を書き換える

プロジェクトフォルダの `wrangler.jsonc` を開き、以下のコメントアウトされた部分を探します:

```jsonc
// "d1_databases": [
//   {
//     "binding": "R2_WRITE_BUDGET_DB",
//     "database_name": "astrosight-r2-write-budget",
//     "database_id": "ここに実際のDatabase IDを入れてから有効化する"
//   }
// ],
```

**先頭の `//` をすべて外してコメントを解除し**、`database_id` の値を、手順1でコピーした実際のDatabase IDに置き換えて保存してください。書き換え後は、こうなります(IDの部分は実際の値に置き換わります):

```jsonc
"d1_databases": [
  {
    "binding": "R2_WRITE_BUDGET_DB",
    "database_name": "astrosight-r2-write-budget",
    "database_id": "実際にコピーしたID"
  }
],
```

**注意**: コメントアウトされたまま(`//`が付いたまま)プッシュしても、アプリの動作に問題は起きません。ただし、D1データベースを作成していない段階でコメントを解除してしまうと、存在しないIDを参照することになり、次回のデプロイが失敗します。**手順1を終えてからコメントを解除してください。**

### 3. テーブルを作成する(初回のみ)

パソコンでプロジェクトフォルダを開き、コマンドプロンプト(またはターミナル)で以下を実行します:

```
npx wrangler d1 execute astrosight-r2-write-budget --remote --file=./migrations/0001_create_r2_write_budget.sql
```

これで、カウンター用のテーブルが本番のD1データベースに作成されます。

### 4. GitHubへコミット・プッシュ

`wrangler.jsonc` の変更を、いつも通りコミット・プッシュしてください。Cloudflare Pagesが自動的に再デプロイします。

## 確認方法

デプロイ後、しばらくアプリを使ってみて、Cloudflareダッシュボードの「D1」→ 作成したデータベース →「Console」タブから、以下のSQLを実行すると、現在の月間書き込み総数を確認できます:

```sql
SELECT * FROM r2_write_budget;
```

## もしこの設定を後回しにした場合

`database_id` が `"REPLACE_WITH_ACTUAL_D1_DATABASE_ID"` のプレースホルダーのままデプロイされた場合、D1データベースへの接続自体ができないため、**月間の書き込み総数チェックは自動的にスキップされます**(今まで通り、1回のリクエストあたりの上限だけで動作し、アプリの動作自体に支障はありません)。ただし、その場合は今回追加した「利用者急増時の課金防止」という安全網が効かない状態になるので、なるべく早めにこの設定を済ませることをおすすめします。
