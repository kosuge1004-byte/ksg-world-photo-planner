# JPGEO2024 ローカル計算データ

AstroSight のジオイド高 `N` は、国土地理院から取得した `geoid/JPGEO2024_isg.zip` 内の
`JPGEO2024.isg` をビルド時生成物へ変換し、Cloudflare Pages Function 内で計算する。
国土地理院の使用承認番号は **国地情使 第402号**（GIS「astrosight」作成のため）。

## 原本の仕様

- モデル: `JPGEO2024`（`Hrefconv2024` を加算しない）
- 形式: ISG 2.0、ASCII テキスト、ヘッダーあり
- 単位: m
- 格子順: 北から南、各行は西から東（`N-to-S, W-to-E`）
- 全範囲: 北緯 15–50 度、東経 120–160 度
- 格子間隔: 緯度 1 分（`1/60` 度）、経度 1 分30秒（`0.025` 度）
- 全格子: 2,101 行 × 1,601 列 = 3,363,701 点
- NoData: `-9999.0000`
- 原本 ZIP SHA-256: `0588895f22f90d508f91b0f865ec189da41e3d1b18782556bcccb9dc5b294d57`
- `JPGEO2024.isg` SHA-256: `687c08d744023226bc75c96542bf239b8c058b5d4c47d1c5104239cd86586685`

CGI の `OutputData.geoidHeight` は `JPGEO2024` と一致する。`HeightReferenceConversion`
（`Hrefconv2024`）は別フィールドであり、たとえば那覇では 0.6840 m ある。既存の
AstroSight は `geoidHeight` を楕円体高変換 `h = H + N` に使ってきたため、ローカル計算も
同じ `JPGEO2024` 単体を使う。

## 配布用生成物

`server/data/jpgeo2024.generated.ts` には、従来 AstroSight が受理していた国内範囲
（北緯 20–46.5 度、東経 122–154 度）の 1,591 × 1,281 = 2,038,071 点を収録する。
この範囲内には NoData がない。

値は 0.0001 m 単位の整数へ変換するため、ISG が公開する小数4桁を一切丸めない。
64 × 64 点単位に分け、先頭値、北端・西端の差分、内部の二次元予測残差として可逆符号化する。
実行時は必要なタイルだけを配列へ復元して LRU キャッシュし、4格子点からバイリニア補間する。
外部通信、タイムアウト、リトライは発生しない。

国内範囲外で ISG 全範囲内の座標だけは、互換性のため既存 CGI をフォールバックとして残す。
通常のスポット検索、一括ダウンロード、ライブ三脚候補探索はいずれも国内範囲なので、同じ
ローカル計算経路を通る。

原本から生成物を再作成するコマンド:

```powershell
npm run prepare:jpgeo2024
```

生成スクリプトは原本のモデル名、座標系・単位、格子範囲・間隔・順序、行列数、
値数、NoData、0.1 mm 単位への無損失変換、可逆差分の範囲を検査し、
不一致があれば生成を中止する。
