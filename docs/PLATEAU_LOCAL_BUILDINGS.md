更新日: 2026-10-11

- 311データセット、38,473論理ファイル、29,360,170建物。
- 保存容量は5,884,585,840 bytes。

- `manifest.ndjson`、データセット別の `manifest-fragments-v1/`、`summary.json`、`verification.json`で状態を管理する。

途中終了後はデータセット別記録から再開する。完成データの実体があるのにルートmanifestだけが不足・移動した場合は、元CityGML本文を再取得せず、ZIPの目次と保存済みgzipを照合してmanifestを再構築する。全件数・建物数・LOD内訳・容量が既存summaryと完全一致した場合だけ修復結果を確定する。

## 自動検査

`PLATEAU-Building-Ingest.cmd`は取り込み完了後、標準検査と全展開検査を順番に自動実行する。標準検査は全manifest行、重複、データセット別件数、全保存ファイルの存在・容量・安全な相対パス、summary集計、manifestから参照されない残骸ファイルの有無を確認する。続く全展開検査は全gzip、全建物行、座標範囲、LOD内訳を確認する。操作やCodexの待機は不要で、進捗と最終結果をデータフォルダーのJSONへ保存する。

元ZIP内に異なるパスで同じファイル名がある場合は、元パスのSHA-256を保存名へ付けて別々に保持する。旧方式の同名衝突を見つけた場合は、そのレコードだけを再取得して修復し、置き換え後の未参照ファイルを削除する。

独立して再検査する場合:

```powershell
npm.cmd run plateau:verify
```

全gzipを展開し、全建物行・範囲・LOD内訳まで確認する長時間検査:

```powershell
npm.cmd run plateau:verify:deep
```

配布ツールでは `PLATEAU-Data-Verify.cmd` と `PLATEAU-Full-Data-Verify.cmd` をダブルクリックできる。進捗は `verification-progress.json`、最終結果は `verification.json` に保存されるため、Codexやブラウザを開いたままにする必要はない。

## アプリでの利用

ローカルDEMサービスは起動時にPLATEAU manifestを読み、0.02度単位の空間索引を作る。検索座標の周囲だけを固定規則で調べ、LOD2以上の明示的な屋根面がある建物について、同じ建物の最高屋根頂点を返す。LOD1だけの建物や不正座標を推測で採用しないため、精度が確定できない地点は既存のPLATEAU 3D Tiles探索へ戻る。

クライアントは保存済み結果、ローカルPLATEAU、既存PLATEAU探索の順に解決する。ローカル結果は既存の地点別JPGEO2024補正を通し、出典を `plateau-measured` として保存する。公式高さとしては保存しない。

## セキュリティ

- 公開要求は座標だけを受け取り、任意パス、ファイル名、一覧、書込み、削除を受け付けない。
- ローカルサービスは既存の認証、本文サイズ、同時実行数、時間制限を使う。
- manifest内のパスも固定形式、ルート内包含、実在ファイル、容量上限を確認する。
- データルートが無い、壊れている、対象建物が無い場合もサービス全体を停止せず、既存経路へフォールバックする。
- ローカル保存先や接続方式は利用者向け画面へ表示しない。

データ本体はアプリZIP、GitHub、Cloudflare、R2へ含めない。今回の作業ではGitHub push、Cloudflare deploy、R2アップロードを行っていない。
