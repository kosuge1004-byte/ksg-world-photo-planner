# Work199 Codex handoff update

Use Work199 as the newest baseline. It supersedes Work198's statement that one global adaptive-demosaic radius of 5 must be used everywhere.

Important correction:
- Dart mathematical reference backend: radius 5.
- Production Native Mobile Stack backend: radius 4, as declared by `MOBILE_STACK_DEMOSAIC_REQUIRED_INPUT_RADIUS` and checked by Native CTest.
- Validity/saturation influence must use `DemosaicEngine.requiredInputRadius` from the backend actually selected for processing.
- Do not restore a hard-coded global radius 5 or 4.

Also preserve the Work199 Linear-DNG binary validity contract: transparency masks generated by the stacking pipeline use only 0 and 255, and the writer rejects intermediate values.

Run the existing Codex-first Flutter/Android checks against Work199. The Flutter/Dart API change (`DemosaicEngine.requiredInputRadius`) makes `flutter analyze` and `flutter test` especially important before device testing.
