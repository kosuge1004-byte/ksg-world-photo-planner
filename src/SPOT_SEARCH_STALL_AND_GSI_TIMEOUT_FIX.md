# スポット検索「終わらない/固定される」対策

## 症状

- 三脚候補の検索（スポット検索）が `running` のまま進捗が止まり、いつまでも終わらない。

## 原因（2点）

1. **国土地理院 標高タイル取得にタイムアウトが無かった**
   - `server/gsiElevation.ts` の `fetchDecodedTile()` が呼ぶ `fetch()` に
     タイムアウトが設定されておらず、国土地理院サーバーが応答しない／極端に遅い場合、
     このPromiseが無期限に解決されなかった。
   - このタイルPromiseは同一タイルを要求する全ての候補計算で共有されるため、
     1回のハングが検索全体を静かに停止させていた。
   - Overpass（OSM周辺情報）側は既に独自タイムアウトがあったが、GSI標高タイルには無かった。

2. **クライアント側に `running` 状態の停滞検知が無かった**
   - `queued` 状態が45秒続いた場合のタイムアウトはあったが、
     `running` に遷移した後は `awaiting-3d`／`complete`／`failed` になるまで無条件に待ち続けていた。
   - Netlify Background Function が実行時間上限などで無応答のまま終了した場合でも、
     画面側はエラーにならず、進捗が止まったまま待機し続ける経路があった。

## 修正内容

- `server/gsiElevation.ts`
  - GSI標高タイル取得に8秒のリクエストタイムアウトを追加（`fetchGsiTileWithTimeout`）。
  - タイムアウト・失敗時は既存の catch 経路で `null` 扱いとなり、
    地形未確認候補としてフォールバックする既存の仕組みに合流する。
- `src/search/backgroundSpotSearch.ts`
  - ジョブの `updatedAt` を監視し、`running` のまま90秒更新が無い場合は
    「検索処理の進行が長時間止まりました」というエラーで待機を打ち切るよう変更。
  - 保存済みのアクティブジョブ状態もクリアし、再検索しやすくした。

## 「候補が0件」について

こちらは上記の停滞バグとは別に、次の場合は仕様上の正常な結果です。

- 指定した焦点距離・画角・時間範囲・精度条件では、天体・被写体・撮影可能地点の
  組み合わせが地形上どこにも存在しない。
- 検索完了時に表示される「検索診断」（日時候補／天体条件通過／三脚計算試行／
  三脚候補成立／見通し通過／サーバー候補、など）で、どの段階で0件になったかを確認できる。
  - 例：`三脚候補成立` は出ているのに `見通し通過` が0 → 地形に完全に遮られている。
  - 例：`天体条件通過` から既に0 → 指定時間範囲内にその天体条件自体が発生しない。
- 0件が続く場合は、時間範囲を広げる／精度モードを下げる／許容画角ずれを広げる、
  などの条件緩和で解決するかを診断内容から判断できる。
