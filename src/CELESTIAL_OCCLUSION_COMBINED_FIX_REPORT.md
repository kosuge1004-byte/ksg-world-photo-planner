# AstroSight 遮蔽判定・再計算・大気差 統合修正報告

実施日: 2026-08-02

## 原因

### 観点A: 該当（DEM僅差域の偽陽性）

従来は次の式で地形遮蔽を確定していた。

```ts
terrainElevation >= celestialAltitude - 0.015
```

この式では、天体高度`10.010°`、地形稜線`10.000°`のように天体が`0.010°`上にある場合でも、`10.000 >= 9.995`が成立して`terrainObstructed: true`になる。回帰テストでこの誤判定を再現した。

旧判定相当の記録:

- 見かけの天体高度: `10.010°`
- 地形稜線角度: `10.000°`
- クリアランス: `+0.010°`
- 旧結果: `reason: terrain`, `terrainObstructed: true`

実機スクリーンショットの撮影地点・時刻・端末内の`occlusion.moon`値は指示書に含まれていなかったため、上記は同じ判定式を通す最小再現値であり、スクリーンショットそのものの実測値ではない。

### 観点B: 古い応答の上書きは未再現、不要な再計算トリガーは該当

非同期経路には既に`cancelled`、`AbortController`、タイマー破棄があり、古い応答が新しい結果を永続的に上書きする経路は確認できなかった。このため世代IDの重複導入は行っていない。

一方、焦点距離と画角は天体の方位・高度を変えないにもかかわらず、焦点距離変更で遮蔽キャッシュを破棄し、太陽・月・北極星を再判定していた。操作中は未確認表示、停止後は観点Aの偽陽性結果が戻るため、「ドラッグ中は円盤、停止後は位置のみ」という症状を発生させる直接のタイミング要因だった。

### 観点C: 症状の直接原因としては未確認、設計上の僅差リスクは該当

プレビュー用気象データは検索ダイアログで取得完了してから一度だけ渡され、操作後に遅れて気象状態が差し替わる実装ではない。そのため、遅い気象応答が今回の表示を後から反転させる経路は確認できなかった。

ただし、天体は大気差補正後の見かけ高度、DEM稜線は幾何高度で比較しており、僅差域の非対称性は残る。地上大気差の係数は気層に左右され、固定係数を加えると別の誤判定を増やすため、今回の修正では地形側へ固定補正を追加していない。

代わりに、従来から存在した`0.015°`を片側の遮蔽マージンとして使うことをやめ、`±0.015°`を未確定帯として対称に扱う応急処置を採用した。僅差では円盤を隠さず、「地形稜線との僅差のため遮蔽は未確定です」と表示する。地形が天体より`0.015°`を超えて明確に高い場合は、従来どおり遮蔽確定する。

## 修正内容

- DEM稜線判定を`visible / obstructed / uncertain`の3区分へ変更。
- 月の見かけ高度、幾何高度、稜線角度、クリアランス、遮蔽距離、DEMソース、失敗理由をプレビューDOMの診断属性へ記録。
- 天体座標計算で大気差適用前の幾何高度を保持。
- 焦点距離・画角・構図補正を太陽・月・北極星の遮蔽再計算条件から除外。
- 天体本体の遮蔽判定と天の川帯の遮蔽判定を分離。ズームで天の川の画角内区間は再評価するが、月などの本体判定は再実行しない。
- タイムライン停止後は日時に対応する遮蔽判定を引き続き実行。
- 中止済み非同期処理の結果を反映しない既存ガードを維持。

## 確認条件

- ズーム後に非遮蔽天体が位置のみ表示へ変わらない: **満たした（焦点距離を本体遮蔽の依存条件から除外し、自動検証済み）**
- タイムライン後に僅差だけで位置のみ表示へ変わらない: **満たした（±0.015°を未確定扱い、日時変更後の再判定は維持）**
- 明確な地形遮蔽を維持: **満たした（天体`9.980°`、稜線`10.000°`を遮蔽とする回帰テスト）**
- 建物・3D遮蔽を維持: **満たした（`dem-and-google-3d / building-or-surface`の既存回帰を維持）**
- 判定中は円盤表示を維持: **満たした（`checking`を遮蔽確定しない既存回帰を維持）**
- 太陽・北極星も同じ競合対策を使用: **満たした（4天体共通の方位高度配列と中止ガードを使用）**
- TypeScript、lint、Webビルド: **満たした**
- 指示書の実機スクリーンショットと同一地点・同一時刻での再確認: **未確認（再現入力値が未提供）**

## 未解決事項

- 地上大気差を固定係数でモデル化していない。逆転層など実気層の影響を正確に扱うには、地点・距離方向の鉛直気象プロファイルが必要。
- 実機固有のスクリーンショット条件は、地点、三脚高、被写体、日時、焦点距離、`occlusion.moon`実値があれば追加照合できる。
