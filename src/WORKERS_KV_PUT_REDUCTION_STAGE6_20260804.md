# Workers KV PUT削減 第6段階

## 結論

通常の新規検索で必要なWorkers KV PUTは、現設計では最小の2回です。

1. `queued` — Queue二重投入防止、開始APIの冪等性、検索開始直後の状態照会に必要
2. `awaiting-3d` — サーバー検索結果を端末へ引き渡し、通信失敗時に復旧するため必要

`queued`を削除すると、開始レスポンス消失時の再送で同一ジョブをQueueへ二重投入する可能性があり、検索開始直後のstatus APIも404になります。そのため削除しません。

## 今回の修正

- `complete`を永続化対象から明示的に除外。
- 最終3D確認はレスポンスのみで完了し、KV PUT 0回を保証。
- 回帰テストを現仕様へ修正。
  - finalize前後で`putCount`が増えないことを検証。
  - KV上は復旧用の`awaiting-3d`を維持することを検証。

## PUT回数

- 通常成功検索: 2回
- 同一開始要求の再送: 0回
- 検索進捗更新: 0回
- 最終3D確認: 0回
- 時間軸・日時・±1分: 0回
- 三脚候補更新: 0回
- DEM取得: 0回
- 人物・天体・軌跡・地図・カメラ更新: 0回
- 検索失敗時: `queued`に加えて`failed`を1回（エラー通知・復旧に必要）
