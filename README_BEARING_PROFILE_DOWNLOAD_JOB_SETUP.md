# 三脚候補周辺データダウンロードの設計方針について (2026-09-09更新)

## 現状（2026-09-09時点）

三脚候補周辺データのダウンロードは、**端末（ブラウザ）が直接処理する方式**です。
1段階（10m/1m地形取得）ごとに45秒のタイムアウトを設けてあるため、通信が
ハングしても永遠に固まりません（2026-09-08のダウンロード停止修正）。

この方式は「他のアプリに切り替えている間も処理が続けば十分」という要件を
満たします。ブラウザには一部で検討したCloudflare Workers側の技術的制限
（1回の処理あたり外部通信50回まで、無料プランの場合）が一切適用されない
ため、この方式であれば安定して動作します。

## 見送った設計（サーバー側バックグラウンドジョブ化）

一時、「アプリを完全に終了しても処理が続く」ことを狙って、Cloudflare
Queue + Workers KVを使ったサーバー側バックグラウンドジョブ方式へ変更を
試みました。しかし実機検証の結果、Cloudflare Workers無料プランの
「1回の呼び出しあたり外部通信50回まで」という上限に、この処理の通信量
（1方位あたり最大64回）が抵触し、実用に耐えないことが判明しました。

有料プラン（$5/月〜）にすれば上限が10,000回まで上がり解決する見込みですが、
「アプリの完全終了までは耐えなくてよい」という実際の要件に照らすと、
追加コストや複雑な設計変更をしてまで解決する必要はないと判断し、
今回は元の直接方式へ差し戻しました。

## 残されているコード

サーバー側ジョブの実装一式（`server/bearingProfileDownloadJobs.ts`、
`server/runBearingProfileDownloadJob.ts`、
`workers/bearing-profile-download-consumer.ts`、
`functions/api/bearing-profile-download-start.ts` /
`-status.ts`、`wrangler.bearing-profile-download.jsonc`）は、
現在は使われていませんが、将来「アプリの完全終了にも耐えたい」という
要件が生じた場合に備えて、そのまま残してあります。作成済みのCloudflare
KV（`BEARING_PROFILE_DOWNLOAD_JOBS`）・Queue（`astrosight-bearing-profile-download`）
もそのまま残しておいて構いません（利用していなくても料金は発生しません）。

これらを再度有効化したくなった場合は、このリポジトリの変更履歴を
参照してください。
