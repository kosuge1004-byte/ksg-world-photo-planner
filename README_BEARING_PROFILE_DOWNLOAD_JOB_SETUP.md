# 三脚候補周辺データダウンロードを「アプリを閉じても進む」方式にする手順 (2026-09-08)

**ターミナルやコマンド操作は一切不要です。すべてブラウザの画面操作だけで完結します。**

## これは何をする作業か（1行で）

Cloudflareのサイトで「保存場所（KV）」と「順番待ちの列（Queue）」という
入れ物を2つ、クリックだけで新しく作ります。あとはGitHubにこのzipの中身を
反映するだけで、残りは全部自動です。

---

## 事前確認: すでに設定済みかもしれません

もし以前 `README_DEPLOY_PREWARM_WORKER.md` の手順（「有名スポット自動
キャッシュ機能」の設定）を完了しているなら、「手順0」の
`CLOUDFLARE_API_TOKEN` はもう登録済みです。その場合は手順0を飛ばして
手順1から始めてください。

## 手順0: （まだの場合だけ）Cloudflareのトークンを作ってGitHubに登録する

1. https://dash.cloudflare.com にログイン
2. 右上のアカウントアイコン →「マイプロフィール」
3. 左メニューの「APIトークン」を開く
4. 「トークンを作成する」→「Edit Cloudflare Workers」テンプレートを選ぶ
5. そのまま「概要に進む」→「トークンを作成する」
6. 表示された文字列をコピーしておく（この画面を閉じると二度と見れません）
7. GitHubであなたのリポジトリを開き、「Settings」→「Secrets and
   variables」→「Actions」→「New repository secret」
8. Name: `CLOUDFLARE_API_TOKEN` / Secret: コピーした文字列を貼り付けて保存

## 手順1: 「保存場所」(KV) を作る

1. https://dash.cloudflare.com にログイン
2. 左メニューから「Workers & Pages」を開く
3. 左メニュー内の「KV」（または「Storage & Databases」→「KV」）を選ぶ
4. 「Create namespace」（namespaceを作成）ボタンをクリック
5. 名前欄に `BEARING_PROFILE_DOWNLOAD_JOBS` と入力して「Add」（作成）
6. 作成された一覧に表示される、32桁の英数字の「ID」をコピーする
   （例: `92197c38d81d48489ef4fdd25b1b9a58` のような文字列）
7. **このIDを、次のメッセージで私（Claude）に貼ってください。** 私が
   `wrangler.jsonc` と `wrangler.bearing-profile-download.jsonc` の
   該当箇所を書き換えます。

## 手順2: 「順番待ちの列」(Queue) を作る

1. 同じ「Workers & Pages」の中の「Queues」を開く
2. 「Create queue」ボタンをクリック
3. 名前欄に `astrosight-bearing-profile-download` と入力して作成
   （これは名前を打つだけで、IDをコピーする必要はありません）

## 手順3: このzipの内容をGitHubに反映する

このzipには、手順0の設定さえ済んでいれば自動的にWorkerをデプロイして
くれる設定ファイル（`.github/workflows/deploy-bearing-profile-download-worker.yml`）
が入っています。私が手順1のIDを設定ファイルに書き込んだ後のzipを、
いつも通りGitHubに反映（プッシュ）してください。それだけで、あとは
Cloudflareが自動的にWorkerをデプロイし、Pages本体も自動的に再ビルド
されます。

---

## 動作確認

1. アプリで三脚候補周辺データのダウンロードを開始する
2. ダウンロード中にアプリを完全に閉じる（タブを閉じる/ホーム画面に戻る）
3. 数分待ってから再度アプリを開く
4. 自動的に完了したデータが取り込まれていれば成功です

## もしこの設定をまだしていない場合

設定前でもアプリは正常に動きます。開始APIが
「サーバー側ダウンロード機能は未設定です」というエラーを返すだけで、
他の機能（スポット検索・三脚候補計算・3D表示など）には一切影響しません。

## 補足: DEMタイル本体のオフラインキャッシュについて

このジョブがサーバー側で計算するのは「360方位ぶんの地形プロファイル」と
「水面・OSM周辺情報」です。地形の生タイルデータそのものの端末への
事前ダウンロードは、今回のスコープには含めていません。三脚候補の最終的な
cm精度確認は読み出し時に必ずライブで取り直す設計になっており
（`tryUseBearingProfileCache`参照）、生タイルの事前キャッシュはあくまで
「次に使う時を少し速くする」ための最適化であって、機能の正しさには
影響しないためです。生タイルは、通常の三脚探索・プレビュー操作で
触れた時点で、これまで通り自動的に端末へキャッシュされます。
